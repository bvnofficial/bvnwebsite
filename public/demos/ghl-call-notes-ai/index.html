Section 01

The Make.com scenario, module by module

One scenario, eleven modules, no duct tape. Every module below has a job and a reason. This is the chain I would build in your Make account, on your GoHighLevel sub account, with your own API keys.

01
Custom webhook, call completed
A GoHighLevel workflow with the Call Status trigger fires on completed inbound and outbound calls and posts contact id, call id, direction, duration and location id to Make.
GoHighLevel
02
Filter, duration is 20 seconds or more
Wrong numbers, voicemail drops and hang ups never reach the AI. This one filter is what keeps the note history clean and the running cost near nothing.
Make filter
03
Sleep, then fetch the call recording
A short delay so the recording finishes writing, then an HTTP call to the GoHighLevel API v2 conversations endpoint to pull the recording for that message id.
HTTP · GHL API v2
04
Router, transcript available or not
If GoHighLevel already has a transcript for the call, use it. If it does not, take the audio file down the second branch instead of failing.
Make router
05
Transcribe the audio
Whisper transcription on the recording, with speaker separation so the AI knows which lines are you and which lines are the seller. Only runs on the fallback branch.
OpenAI
06
Pull contact context
Fetch the contact from GoHighLevel so the AI sees the property address, the pipeline stage and any earlier notes. Context is the difference between a summary and a useful note.
GoHighLevel
07
AI summarise, structured JSON out
One call to the model with a locked real estate prompt and a strict JSON schema covering motivation, property, price, objections, next steps and follow up. JSON, not prose, so nothing downstream has to guess.
OpenAI
08
Parse JSON and format the note
Turn the structured object into the clean note layout shown in the next section, so it is readable at a glance inside the contact timeline.
Make JSON
09
Create the note on the correct contact
POST to the contact notes endpoint using the contact id that came from the call itself, so the note can never land on the wrong record.
GHL API v2
10
Write the signals back to fields and tags
Motivation level, asking price and timeline go into custom fields. Tags like seller motivated high or objection price get applied so your pipeline and filters actually move on their own.
GoHighLevel
11
Error handler with retry and alert
Break directive with three retries on the API modules, a data store to stop duplicate notes, and a message to you if a call ever fails to process. Silence is never treated as success.
Make error route

Section 03

The prompt contract

The model is not asked to write nicely. It is asked to fill a fixed schema and to leave a field empty when the call did not cover it. That single rule is what stops AI notes from quietly inventing a price that was never said.

// AI module output, enforced schema
{
  "motivation":      { "summary": "string", "level": "high | medium | low | unknown" },
  "property":        { "beds": "string", "baths": "string", "condition": "string", "occupancy": "string" },
  "price":           { "seller_ask": "string", "range_discussed": "string", "flexible": "boolean | null" },
  "objections":      [ "string" ],
  "next_steps":      [ { "action": "string", "owner": "me | seller", "due": "date | null" } ],
  "follow_up":       { "when": "date | null", "channel": "call | text | email" },
  "tags":            [ "string" ]
}

// Rules baked into the system prompt
// 1. Never state a number the seller did not say.
// 2. Empty string beats a guess. Unknown is a valid answer.
// 3. Quote the seller when the wording carries the motivation.
// 4. Next steps must be actions, not observations.
Section 04

The parts that decide whether you trust it in month three

Anyone can wire the happy path. Clean and reliable is what happens on the other days.

No duplicate notes

Every processed call id is written to a Make data store and checked first. A replayed webhook or a manual rerun cannot post the same note twice.

Recording not ready yet

The recording can lag the call end. The scenario waits, then retries three times before it sends the call down the fallback branch instead of dying.

Cost stays small

The under 20 seconds filter runs before any AI module, so you never pay to summarise a voicemail. Long calls are chunked so nothing hits a token wall.

Wrong contact is impossible

The contact id comes from the call payload itself, never from a phone number lookup, so shared numbers and duplicate records cannot misroute a note.

You get told when it breaks

The error route posts the call id and the reason to you. A failed call is visible the same day, not discovered a month later.

You own all of it

Your Make account, your GoHighLevel sub account, your OpenAI key. Documented scenario, named modules, a written one page runbook. No lock in to me.
